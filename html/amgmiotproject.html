Overview
Challenge: AceMicromatic's shop floors generate high-frequency machine data — spindle load, temperature, cycle counts, alarms — from hundreds of machines per plant. The existing web dashboard polled a REST endpoint every 5 seconds, which meant stale data, unnecessary bandwidth, and no mobile experience at all. Operators on the move had no way to monitor KPIs or respond to alerts until they returned to a desk.

Approach: I architected the Flutter mobile client around SignalR persistent connections multiplexed by plant and machine group, so real-time KPI tiles and alert streams update without polling. On the Blazor dashboard side, I designed the state flow to batch UI updates on a configurable interval — decoupling render cycles from wire events so the interface stays responsive even when hundreds of machines broadcast status changes per second. I also implemented a local cache layer with exponential-backoff reconnection so the app never shows a blank screen on intermittent networks.

Key decision — SignalR over polling: Moving from 5-second REST polling to WebSocket-backed SignalR cut latency from ~5 s to <200 ms and reduced bandwidth by roughly 60% on the critical data path. The trade-off was more complex reconnection logic — I implemented exponential backoff with jitter and a local cache so the mobile app stays usable during signal drops. The data refresh rate on critical KPI tiles is ~100 ms over the WebSocket path, with non-critical data batched to a 2-second interval.

Impact: The app serves 2,000+ industrial users across iOS and Android, with six major updates shipped through the full release pipeline — TestFlight beta distribution, phased rollouts, and Firebase crash monitoring. Push notifications (FCM/APNs) deliver downtime alerts and KPI threshold breaches with context-deep links so a tap opens the relevant machine detail view.

I owned the mobile client end-to-end — architecture, state management, SignalR integration, offline resilience, and App Store / Play Store releases — while a backend team maintained the SignalR hubs and SQL Service Broker triggers on the server side.
