Overview Highlights
Replacing four apps and four accounts with one encrypted local database.
Context: Most people run a separate app for tasks, notes, bookmarks, and finances — each with its own account, its own cloud dependency, and its own copy of your data sitting on someone else's server. Everything App started from a narrower question: how much of that actually needs a server at all? The answer, for one person's daily use, turned out to be almost none of it.

My role: Solo — architecture, all four modules, and the encryption layer.

Approach: The app is four bottom-nav modules — Dashboard, Tasks, Library, Finance — plus global search and settings, all reading and writing to a single local database. Everything is layered service → repository → bloc → view, built on BLoC, Drift, Dio, and GoRouter.

Storage and security: The database is SQLite compiled as SQLCipher, giving AES-256 encryption at rest for everything the app stores. The Vault — the module holding passwords and documents — adds a second layer on top: AES-256-GCM per item, so a compromised database dump still doesn't expose individual vault entries in the clear. Tokens and credentials never touch app-level cache; they live in flutter_secure_storage, isolated from the rest of the app's state.

Assistant — deterministic first, AI second: You can add a task or log a transaction by typing a sentence. The core parsing is rule-based: instant, deterministic, and fully offline — the assistant works the same with no network at all. Prose-heavy paths — summarizing a document, answering a grounded question — are backed by the Gemini API when a key is configured, but that's an extension, not a dependency. I chose this order deliberately: an assistant that only works when a cloud model is reachable isn't reliable enough to be a core input method, so the rule-based engine had to stand on its own first.

Backup without an OAuth stack: Backup and restore hands an encrypted file to the OS share sheet rather than integrating cloud storage APIs directly. This was a scope decision, not a shortcut — the OS already solves "get a file into a specific cloud provider" better than a single-developer app can, so I didn't rebuild it. The user picks Drive, Dropbox, iCloud, or anything else already on their device; the app just needs to hand off an encrypted blob.

Library, consolidated: Five things that don't usually live together — Bookmarks, a To Buy list, a Watchlist, the Vault, and nestable Projects with a built-in Markdown editor (live preview, export to Markdown/text/PDF) — share one home instead of five separate apps. Headlines on the Dashboard open in the device browser rather than an in-app webview, on the same logic as the backup decision: the article belongs to its publisher, not to this app.

Offline by default: The network is only ever touched for three things: weather, news, and the optional Gemini path. Tasks, Finance, Library, search, widgets, notifications — all of it works with no connection.

Impact: Four app categories consolidated into one — tasks, notes/bookmarks/documents, finance, and daily planning. AES-256 at rest, plus per-item AES-256-GCM on the Vault. Fully offline except three explicitly-scoped network features. Native home screen widgets on both platforms — Android AppWidgetProvider and iOS WidgetKit, not a lowest-common-denominator cross-platform shim. Zero account, zero server — nothing about using the app requires trusting a backend that doesn't exist.

Status: Store submission polish — no functional gaps in the four core modules, but a final pass on onboarding, notification permissions flow, and platform-specific store requirements before Play Store and App Store release.
