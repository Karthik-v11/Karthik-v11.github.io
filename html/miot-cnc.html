Overview Highlights
Keeping a live dashboard honest when data never stops moving.
Context: AceMicromatic's shop floors generate high-frequency machine data — spindle load, temperature, cycle counts, alarms — from hundreds of machines per plant. The existing web dashboard polled a REST endpoint every 5 seconds: stale data, wasted bandwidth, and no mobile experience at all. Operators on the move had no way to monitor KPIs or respond to alerts until they returned to a desk.

My role: I owned the mobile client end-to-end — architecture, state management, SignalR integration, offline resilience, and App Store / Play Store releases — while a backend team maintained the SignalR hubs and SQL Service Broker triggers on the server side.

Approach: I architected the Flutter mobile client around SignalR persistent connections multiplexed by plant and machine group, so real-time KPI tiles and alert streams update without polling. On the Blazor dashboard side, I designed the state flow to batch UI updates on a configurable interval — decoupling render cycles from wire events so the interface stays responsive even when hundreds of machines broadcast status changes per second. The redesign replaced a dense desktop-first KPI grid with a mobile-first dashboard: the critical KPIs — spindle load, temperature, cycle counts — surface as live tiles with a separate alert stream, so a phone can be read at a glance. I also implemented a local cache layer with exponential-backoff reconnection so the app never shows a blank screen on intermittent networks.

Key decision — SignalR over polling: Moving from 5-second REST polling to WebSocket-backed SignalR cut latency from ~5 s to <200 ms and reduced bandwidth by roughly 60% on the critical data path. The trade-off was more complex reconnection logic — I implemented exponential backoff with jitter and a local cache so the mobile app stays usable during signal drops. The data refresh rate on critical KPI tiles is ~100 ms over the WebSocket path, with non-critical data batched to a 2-second interval.

Why push notifications: Downtime alerts and KPI threshold breaches arrive as native push (FCM/APNs) rather than in-app polling — an operator's phone can't keep a polling loop alive without draining the battery or missing alerts entirely. Each notification carries a context-deep link so a tap opens the exact machine detail view.

Impact: The app serves 2,000+ industrial users across iOS and Android, with six major updates shipped through the full release pipeline — TestFlight beta distribution, phased rollouts, and Firebase crash monitoring.
